# 后续交付

- M3 已完成增量：节点只读列表/详情、Ready 与压力条件、容量/可调度容量、采集新鲜度及前端展示；cordon/uncordon 的持久化操作、UID 校验、幂等和恢复观察。
- M3 drain 的独立 CPU 集群验收：已加入平台 Pod 归属核验、DaemonSet/镜像 Pod 跳过、非托管 Pod/本地数据保护、Eviction API 与 PDB 限流处理、blocked 操作恢复；真实正常迁移、非托管 Pod 阻止、PDB 拒绝与解除、幂等冲突、执行器重启恢复，以及 emptyDir/hostPath 阻断与解除后的迁移均已通过。项目 `NODE_DRAIN_ENABLED` 默认关闭，实验后恢复 `node_drain=false`。这仅证明该独立 kind 环境中的 CPU 路径，不代表生产节点或 GPU 工作负载验收。
- M3 节点资产已新增架构、系统版本及 GPU Feature Discovery 型号/驱动标签的白名单投影；当前 CPU kind 环境没有 GPU 标签，真实 GPU 型号、驱动和设备健康仍未验收。节点资产与业务记录的持久关联、设备来源与健康、受控标签及逐节点镜像预热仍待开发。Kubernetes 1.34 的 image volume 默认关闭，预热机制需先验证运行时支持。`image_prewarm=false`。
- 工作负载诊断已加入当前 Pod 异常事件的受限摘要和控制台入口；GPU 实时利用率/显存/温度仍未接入。后续应通过独立遥测适配器消费 DCGM Exporter，明确指标时间、缺失与过期状态，不把 Kubernetes `nvidia.com/gpu` 容量当成利用率。
- 多架构 OCI/Docker 镜像索引已增加代码级核验与架构亲和条件；还需在独立测试仓库执行真实多架构推送、父 digest 拉取及不同架构节点调度验收。
- M4：先对可访问的 DGX Spark 做独立 ARM64/GPU 接入试点，核实其系统、Kubernetes、驱动、仓库网络与镜像拉取；随后在真实 B300 环境锁定硬件/驱动/运行时/GPU Operator 兼容基线，验证整卡分配、真实计算和停止后释放。两种硬件分别记录验收，不互相替代。带外操作仅在接口和授权策略确定后实现。
- M5：分批纳管 64 节点/512 卡、容量与并发拉取验证、集群/数据库/仓库恢复演练、长连接维护约定。
- 生产增强：多主体项目映射配置与管理、凭据引用型环境配置、只读机器人轮换自动化、操作取消/受控强制终止、速率限制、审计保留策略、依赖告警和正式部署最小权限角色。
- 简易管理前端已按后续需求补充：资源概览、创建服务、启停、扩缩容、删除、操作查询。镜像推送和配置版本更新仍使用 API/脚本。
